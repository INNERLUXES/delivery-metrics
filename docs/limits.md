# What the numbers do not tell you

- **They describe the records, not the team.** A deployment that is not in the file did not happen, for this tool. Check the records before reading the result.
- **Commit time is not work start.** Lead time runs from the commit, so work done before the first commit, and time spent waiting for review, are only partly counted. A team that commits late looks faster than it is.
- **A failed deployment is what you mark as failed.** Teams differ on whether a hotfix, a feature flag switched off or a partial rollback counts. Decide once, write it down, and keep to it, or the change failure rate drifts for reasons that have nothing to do with quality.
- **Small numbers swing.** With ten deployments in a month, one failure moves the rate by ten points. Read weekly rows as a trend, not as a score.
- **Time to restore needs honest start times.** An incident logged an hour after users noticed it shortens the measured time by an hour.
- **No benchmark is built in.** Published bands change between reports and between kinds of software. Compare your numbers with your own earlier numbers first.
